# 4.4.1 Use Case Specifications (Most Important)

## UC-01: Upload or Update Dataset
- Primary actor: UI/UX Designer, Admin
- Goal: Add new rows or update existing rows in the color dataset.
- Preconditions:
  - Backend API is running.
  - Actor has dataset row fields (id, platform, year, primary, background, text_color).
- Main flow:
  1. Actor enters row data in Dataset page.
  2. Frontend sends PUT /update with row payload.
  3. Backend validates payload and row id.
  4. Backend creates or updates row in local storage and attempts Supabase sync.
  5. Backend returns success message and updated count.
- Alternative flows:
  - Invalid payload -> HTTP 400 with validation error.
  - Row id not found for delete -> HTTP 404.
  - Supabase unavailable -> local JSON remains source of truth.
- Postconditions:
  - Dataset row exists in local storage.
  - Updated data is visible in frontend table.

## UC-02: Analyze Color Trends and Accessibility
- Primary actor: UI/UX Designer
- Goal: View color frequency, trends by year, platform analysis, and WCAG pass/fail summary.
- Preconditions:
  - Dataset contains at least one valid color row.
- Main flow:
  1. Actor opens Analysis page.
  2. Frontend calls GET /analysis.
  3. Backend loads data from Supabase or local fallback.
  4. Backend computes frequency, year-wise trends, WCAG checks, and platform-level statistics.
  5. Backend returns analysis payload.
  6. Frontend renders charts and summaries.
- Alternative flows:
  - Supabase read fails -> backend uses local dataset fallback.
  - Invalid color values -> marked as invalid in WCAG summary.
- Postconditions:
  - Actor sees a complete trend and accessibility dashboard.

## UC-03: Generate WCAG-Compliant Recommendation
- Primary actor: UI/UX Designer
- Goal: Get readable text color recommendation for selected background color.
- Preconditions:
  - Actor provides valid HEX color.
- Main flow:
  1. Actor inputs or selects a color.
  2. Frontend calls GET /recommend/:color.
  3. Backend validates HEX and computes contrast against white and black.
  4. Backend returns best text color, contrast ratio, and WCAG status.
  5. Frontend shows recommendation preview.
- Alternative flows:
  - Invalid HEX value -> HTTP 400 with error message.
- Postconditions:
  - Actor receives actionable WCAG recommendation for UI text color.
